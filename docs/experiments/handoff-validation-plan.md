# 第一轮 BOSS 交接验证实施计划

目标：在Ubuntu22.04/A10080GB上运行固定BC权重的原始、CH1、CH2及CH3诊断；先获得可信实验记录，不实现创新算法。

用户已授权修改代码并准备服务器实验。默认BC；用户暂无策略权重，从原示范训练。用户将在服务器按README放置根目录assets及datasets/libero_90，脚本采用这两个默认路径，并兼容已整理的datasets/boss_44，不再要求本地数据路径。

1. 最小修复SequentialEnv的seed、reset和切换观测；使用真实类方法加轻量环境替身先复现错误再修复。保留原有自动技能切换语义。
2. 新增独立BC诊断入口：逐episode运行，避免20份模型深拷贝；明确seed、初态索引、步预算、reset模式；存JSONL、汇总、交接状态/图像。原评估入口保留；修复后的诊断协议与旧脚本差异写明。
3. 新增纯标准库准备/预检和聚合工具：校验数据路径与文件、非破坏性准备boss_44、动态生成服务器路径配置、拒绝缺失权重/覆盖结果；RPD零基线NA、条件后继率分母明确。
4. 提供BC固定依赖、Ubuntu安装和训练/评估脚本；CUDA_VISIBLE_DEVICES选择物理GPU，模型使用cuda:0；先smoke再20episodes×3seed。
5. 本地运行标准库/NumPy单元测试、语法编译及CLI dry-run；未安装PyTorch/MuJoCo，真实CUDA/EGL/训练留服务器验证，不声称复现。

预期对照：CH1/CH2各自映射回同一原技能；CH3 reset=original对比reset=none。取消归位仍跨环境传递MuJoCo state，不等价于完整无缝物理执行。

阶段成功率、前缀成功率、条件后继率、完整链成功率、逐任务RPD和耗时均输出。此轮不自动把历史目标失效判为义务破坏，也不把单次失败分类为视觉或物理原因；交接快照用于下一轮配对干预分析。
